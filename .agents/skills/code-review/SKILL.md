# 代码审查

1. 明确审查范围并查看 Git 状态和相关 diff；阅读调用方、配置、测试及 [联合实现说明](../../../REPRODUCTION.md)。不要改动用户未提交的工作。
2. 检查 tensor 形状、设备/dtype、梯度和冻结范围、检查点兼容性、DDP 同步、损失掩码及边界；按相关性检查数据划分泄漏、时序因果性、记忆状态重置、在线/训练路径差异、坐标变换、空样本和性能开销。只报告有具体触发条件及实际影响的问题。
3. 参照 `tests/` 和相关代码确定覆盖缺口；选择安全、轻量的验证。默认不启动长训练、大规模评测，不声称未运行的测试通过。

输出：按严重程度排列的发现，每项包含文件与行号、触发条件、影响和修复或验证建议；再列实际检查、未运行测试与剩余风险。无发现时明确说明并保留验证局限。

本分支资料入口：[README](../../../README.md)、[复现说明](../../../REPRODUCTION.md)、[本分支研究记录](../../../reports/reproduction/WORLD_MODEL_IMPLEMENTATION.md)；历史报告需核对日期、配置和适用范围。
