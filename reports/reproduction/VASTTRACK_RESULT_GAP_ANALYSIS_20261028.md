# VastTrack 单数据集训练与论文成绩差距分析

核查日期：2026-10-28。依据实际训练运行目录的冻结源码、配置、权重初始化记录与已保存预测。此次分析未重新训练，也未新增 GPU 评测；诊断性重计分不覆盖原始成绩。小型运行证据现已随 Git 保存于[本轮归档](vasttrack_run_20261026/README.md)；下文核心源码链接指向与冻结快照相同的仓库实现。

结论：已确认训练分布与论文不同，并且当前权重在外部数据集的语言定位和跟踪上确实较弱。缺少 LaSOT/TNL2K 训练数据是优先验证的原因，但没有控制变量实验，不能说它解释了全部差距，也不能承诺补齐数据就恢复论文成绩。

## 1. 差距有多大

论文应比较 Table 1 的 **Tracking-by-language** 行。带初始框的另一行属于不同任务。

| 数据集 | 论文 language-only AUC | 本次 E60 严格 language-only AUC | 相差（百分点） |
| --- | ---: | ---: | ---: |
| TNL2K | 57.80 | 37.14 | -20.66 |
| LaSOT | 60.70 | 51.52 | -9.18 |
| OTB99-Lang | 60.70 | 52.70 | -8.00 |

本次 TNL2K 评测 699 条，另 1 条因语言为空排除；LaSOT 280 条；OTB99-Lang 48 条。OTB99-Lang 原始协议本来将 51 条用于训练、48 条用于测试，因此不能把 48 条直接说成“漏测了另外 51 条”。

最可靠的同条件对照：已完成的 OTB 官方权重与本次权重使用相同严格首帧预测、相同参数、相同 48 条序列。官方 AUC **60.5249**，本次 **52.6971**，相差 **7.8278** 个百分点；官方在 35 条更好，本次在 13 条更好。主要差距不是仅仅由于评测流程更严格。

## 2. 已确认最大的训练条件差异：数据分布

实际只使用 VastTrack 的 46,325 条训练序列，另预先留出 500 条内部验证。官方配置从 LaSOT、VastTrack、TNL2K_train 以 **1:1:1 的数据集抽样概率**取训练样本；这不是三个目录的原始帧数比例。

本次 60 轮共约 600 万成功训练样本，全部来自 VastTrack。相同样本预算下，官方混合方案每个数据集约贡献 200 万。重复抽更多 VastTrack 样本不能替代完全没有见过的另两种训练分布。这种差异与 TNL2K 的最大跌幅相容，但不是因果证明。

证据：[实际运行规格](vasttrack_run_20261026/training/run_spec.json)、[实际训练配置](vasttrack_run_20261026/training/config.yaml)、[官方配置](https://github.com/inha-vllab/MVLM/blob/main/experiments/mvlm/mvlm_TF.yaml)。

## 3. 高训练 IoU、高内部验证分数为何不能保证外部效果

训练 search 输入由 GT 框扰动后裁剪，factor=4、中心扰动=3.5、尺寸扰动=0.5，输出 224×224。训练 IoU 0.877 是在这样的目标附近裁剪中计算的单帧定位统计，不测量整图语言定位、长序列漂移和失败后的重新定位。该方式继承官方实现，不是本次新增的错误。

证据：冻结源码 [processing.py](../../lib/train/data/processing.py) 第 199–241 行、[processing_utils.py](../../lib/train/data/processing_utils.py) 第 30–39 行、[actor](../../lib/train/actors/mvlm.py) 第 58–79、138 行。

内部验证和外部测试本身也不同：

| 集合 | 序列数 | 平均帧数 | 帧数中位数 |
| --- | ---: | ---: | ---: |
| VastTrack 内部验证 | 500 | 79.8 | 48 |
| OTB99-Lang 测试 | 48 | 605.8 | 394 |
| TNL2K 测试 | 699 | 737.8 | 520 |
| LaSOT 测试 | 280 | 2447.7 | 2102 |

内部验证有 79.8% 的序列不足 100 帧。其 70.43 AUC 不能当作超过论文外部测试成绩的证据。长度体现分布差异，但不能单独证明失败原因；TNL2K 首帧也有明显问题。

内部验证排除无效 GT，外部按原评测约定把无效帧计失败。将内部 603 个无效帧也计失败，AUC 只从 70.4254 降至 70.0907，约 0.33 个百分点。指标分母差异不能解释主要跨域差距。

## 4. 失败不只出现在长视频后半段：首帧语言定位已较弱

首帧预测 IoU < 0.1，即预测与 GT 几乎不重叠的比例：

| 集合 | 首帧 IoU < 0.1 |
| --- | ---: |
| VastTrack 内部验证 | 16.6%（83/500） |
| TNL2K | 38.6%（270/699） |
| LaSOT | 32.1%（90/280） |

TNL2K 首帧 IoU ≥ 0.5 的子集 AUC 为 54.22，首帧 IoU < 0.1 的子集为 22.54。说明全局语言定位/后续恢复值得优先诊断；这是相关关系，不能证明某一种训练设置是唯一原因。

OTB 的 Biker、Surfer、KiteSurf、DragonBaby 语言明确要求头或脸，本次首帧预测框面积为 GT 的约 10.7–20.8 倍。其中一些序列官方也首帧失败，但后续恢复显著更好，不能只把差距归为首次定位。实际训练清单中有 Face 91 条、Head 79 条，不能说 VastTrack 完全没有这两类。

已保存的官方 TNL2K 部分结果有 199 条可配对：同子集本次 AUC 36.09、官方 54.92。这是被取消任务按完成顺序留下的非随机子集，仅用于局部诊断，不能外推为官方全测试成绩。此次没有重新运行官方评测。

## 5. 已排查和仍未闭合的条件

已排查：

- 实际训练快照中的 FastITPN、actor、CM loss、processing、sampler、CLIP 封装与缓存的 upstream/main 核心实现一致，未发现新增模型或损失计算偏差。
- FastITPN 预训练映射 84,342,400 / 84,343,936 个参数，仅跟踪新增 cls_token、fc_norm 共 1,536 个参数未映射。不是整个视觉骨干随机初始化。
- CLIP 冻结符合本次设计；视觉骨干、语言投影和预测头参与训练并已核对更新。推理权重核查没有非 CLIP 缺失键或意外键。
- 把已保存预测仅在计分时将首帧替换成 GT，OTB/TNL2K/LaSOT AUC 分别仅增加 0.1643/0.1610/0.0264。没有重跑原始初始化，因此不能衡量轨迹连锁影响；不过 OTB 同协议官方对照已证明主要差距仍然存在。
- 第 10/20/30/40/50/60 轮内部验证 AUC 为 66.44/67.64/68.63/68.32/69.13/70.43，不支持“第 60 轮明显训练崩溃”的说法，也不能据此确定外部测试的最佳轮次。

尚需核定：

- **有效 batch 与优化步数**：本次 8×10=全局 80，75,000 次更新。论文写 batch=80、4 张 A6000，但没有明确全局还是每卡。官方 YAML 写 80，loader 又直接作为每进程 batch；直接照 README 的四卡例子执行，会得到全局 320、每轮约 312 步。官方发布 checkpoint 顶层仅 net，未含 batch/optimizer 元数据。因此不能确认本次优化条件与作者一致，也不能直接断言作者实际就是全局 320。
- **阈值是否适合新权重**：已按用户要求使用历史最优参数，而非默认值。但历史参数针对官方权重在测试集上得到，新权重的置信度分布可能不同。其影响需要在独立验证集上验证，不能靠再次扫测试集宣称复现。
- **划分独立性**：训练/内部验证序列名交集为 0，但还没有完成同源视频、图像近重复的审计。

## 6. 下一步最能回答原因的实验

1. 先核对三数据集官方训练划分、有效 batch 的解释、初始化与固定推理/计分规则；保留已知测试集调参历史。
2. 在相同全局 batch、总样本数、更新次数、学习率日程和初始化下，对比 VastTrack-only 与 LaSOT:VastTrack:TNL2K_train=1:1:1，其他条件保持一致。这个实验才能估计补齐训练分布带来的收益。
3. 用不含测试序列的验证集选择检查点与阈值，额外观察首帧定位成功率和失败后恢复，最后固定设置报告三个外部测试集。

目前不建议仅凭训练 loss 继续延长当前单数据集训练，也不应承诺增加轮数或补齐两套数据就必然达到论文成绩。
