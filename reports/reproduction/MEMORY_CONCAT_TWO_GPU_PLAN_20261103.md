# 记忆拼接 CENTER：两卡首轮训练方案

日期：2026-11-03（北京时间）；分支：`codex/xmem-concat-center`。
状态：建议方案，尚未启动；本文参数不是已验证最优配方，也不是可直接启动的现有配置。

## 目标与资源

先用固定 4,000 次优化器更新，检验新增记忆通道能否在保留基线定位能力的同时获得收益。
不从零训练整个 MVLM，不沿用已暂停实验的输出目录。
核查时 GPU4、5 空闲、GPU6、7 正在运行原检查点评测；建议正式训练仅使用物理4、5，
启动前重新确认空闲。训练与新验证依次使用同一组两卡，不借用6、7。

## 初始化、冻结与学习率

第一轮从官方无内容记忆的 `models/MVLM_TF.pth.tar` 初始化，与已有 xmem 研究保持明确来源。
扩展 CENTER 的旧512通道复制基线权重，新256通道置零，检索模块随机初始化。
本地自训检查点可作为后续独立对照，不混用其来源与官方基线结果。

| 模块 | 状态 | 峰值学习率 |
| --- | --- | ---: |
| FastITPN视觉编码器 | 全部冻结，保持eval | 0 |
| CLIP及原始文本编码器的语言投影 | 全部冻结，保持eval | 0 |
| 记忆模块的视觉/文本投影、双路检索、位置编码、读取门控 | 训练 | 1e-4 |
| CENTER全部卷积，包括新增输入通道 | 训练 | 1e-5 |
| CENTER BatchNorm仿射参数 | 随预测头训练 | 1e-5 |
| CENTER BatchNorm运行均值/方差 | 冻结，使用初始化统计 | 不适用 |
| 运行时短期/长期记忆条目 | 非优化器参数，每片段/视频重新初始化 | 不适用 |

CENTER使用较低学习率是减少已有定位能力漂移的首轮假设，不是已有因果结论。
新增通道属于整个卷积权重张量，本方案不宣称可以仅靠普通优化器参数组给同一张量的
旧/新通道分别设置学习率。冻结BN运行统计与冻结其可训练仿射参数是两个独立选择。

## 数据方案

使用已准备的官方训练部分：LaSOT 1,120、VastTrack本地有效46,825、TNL2K有效1,299条，
按数据集1:1:1概率抽样。继续排除VastTrack已知11条缺帧视频和TNL2K
`Fight_game_004-Done`，不修改源数据。

正式微调前，从上述训练部分按视频/同源组冻结一个新验证划分：目标LaSOT30、VastTrack60、
TNL2K60条，共约150条，并从本轮训练清单移除；同源分组可能使实际条数略有偏差。
划分种子20261018，保存有序清单、SHA256、排除项和分组规则。
该留出集用于本轮记忆微调选择检查点；官方初始化可能已用过这些训练视频，不能把它
解释为整个模型从未见过的视频或独立最终测试。

本轮不使用旧自定义划分：它曾将部分标准测试视频重新分配作训练，适合历史结构探索，
不适合直接继续后再汇报完整标准基准成绩。
OTB99-Lang、LaSOT、TNL2K的官方测试部分不参与本轮训练和验证选模型。

## 首轮参数与日程

| 项目 | 建议设置 |
| --- | --- |
| 两卡并行 | 2个DDP进程，物理GPU4、5 |
| 每卡batch | 暂定8个视频片段；须先做显存预检 |
| 全局batch | 16个片段，无梯度累积 |
| 每片段 | 4帧，严格递增，采样步长1～4 |
| 每轮采样 | 16,000个片段，即1,000次更新 |
| 首轮预算 | 4轮/4,000次更新，64,000次片段抽取、256,000次搜索帧抽取 |
| 优化器 | AdamW，betas=(0.9,0.999)，eps=1e-8，weight decay=1e-4 |
| 0～200步 | 两个参数组从各自峰值的0.1倍线性预热到峰值 |
| 201～3,000步 | 记忆1e-4，CENTER1e-5 |
| 3,001～4,000步 | 记忆1e-5，CENTER1e-6 |
| 损失 | 2×GIoU + 5×L1 + Focal，逐帧平均；CM关闭 |
| 梯度裁剪 | 全部可训练参数总范数1.0 |
| 精度 | FP32，首轮不新增AMP或EMA |
| 搜索输入 | 224×224，factor4.0，中心扰动3.5，尺度扰动0.5 |
| 增强 | 沿用片段一致的灰度、翻转、颜色扰动与归一化 |
| 数据加载 | 每卡2个worker，计算线程每进程1个 |
| 记忆容量/ROI | 短期8、长期16，每条2×2 ROI token |
| 训练历史写入 | 预测框概率0.5，其余用训练真值框；写入质量门槛0.5 |
| 随机种子 | 20261018，记录rank偏移 |
| 监控 | 独立W&B run和完整本地记录，每20步上传，主进程汇总两卡 |

batch是片段数，16×4=64帧是每步全局搜索帧数，不等同于batch64个独立视频。
单卡8片段的显存占用尚未实测；预检若需降低batch，应在正式启动前固定新配置、
重新核算每轮更新数和采样预算，不能把原4轮直接解释成相同4,000步。
预检和正式训练使用独立输出，正式实验重新从初始化权重加载。
四帧首轮只检验接入与短时收益，不证明长期记忆已学好。

## 验证、对照和停止规则

1. 先在新验证集上运行相同协议的未微调基线，建立可比参照；不能复用旧159条验证的60.73。
2. 每500步保存模型、优化器、调度器、global_step及恢复所需状态；记录恢复的实际边界。
3. 冻结一个30条快速验证子集，每个训练来源10条，在1,000/2,000/3,000/4,000步检查。
   子集分数只作趋势监控，不称为完整验证分数。
4. 2,000步与4,000步做完整约150条验证，必要时再复核一个不同的子集高分检查点。
   按完整验证的三来源等权平均AUC选候选，同时保留固定终点4,000步。
5. 验证时暂停训练并释放训练进程占用的显存，复用物理4、5；全过程不占用6、7。
   推理参数与首帧协议固定，不在测试集搜索阈值。验证进程数依显存预检决定。
6. 记录各来源PRE/NPR/AUC、记忆写入率、空库比例、门控和特征尺度、损失、学习率与资源。
   不能只以训练loss下降或训练IoU上升判定改进。
7. 固定4,000步预算；仅非有限损失/参数、进程异常等运行故障立即终止并诊断。
   不自动延长到20,000步或解冻骨干。若验证结果支持延长，再单列8/12帧实验。

要归因于拼接，应再用同样两卡、全局batch、冻结/BN策略、学习率、数据、初始化及预算
重跑残差对照。历史8卡×每卡2片段的结果仅作背景，其BN、学习率与划分不等价。
如果首轮有改善，冻结方案后再做多种子复核和标准测试，不拼接不同检查点的各集最高分。

## 正式启动前尚需落实

当前 `mvlm_TF_memory_concat.yaml` 仍是旧自定义划分的4,000步示例；不能直接冒充本方案。
当前记忆优化器只有一个学习率组，CENTER的BN运行统计仍随train更新，验证代码也围绕旧清单。
要执行本方案，需要先完成：

- 新的训练/验证清单和数据审计；移植本地已知异常序列的过滤支持。
- 独立两卡配置、记忆/CENTER两组学习率、按step预热与衰减、BN统计冻结。
- 面向新验证集与concat配置的验证队列，解除训练显存后复用同一两卡。
- 源码/权重/清单哈希、独立输出和W&B、恢复状态与实际参数审计。
- 仅10～20步的真实双卡预检：显存、同步、梯度、冻结模块与BN统计均正确。

两卡吞吐和验证耗时尚未实测，启动前依据预检估算ETA，不把此前原模型训练耗时直接搬来。

BN行为依据：本机PyTorch1.13实现及[PyTorch BatchNorm文档](https://docs.pytorch.org/docs/stable/generated/torch.nn.modules.batchnorm.BatchNorm2d.html)。
首轮训练预算依据本项目旧4,000步联合训练与20,000步退化记录，非XMem论文原配方。
