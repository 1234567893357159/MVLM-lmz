# B 阶段训练范围与显存核查

日期：2026-11-11（北京时间）。本次只核查，未修改 A/B 正式训练范围、配置或优化器。

结论：当前 B 是冻结跟踪基线、只更新融合适配层的实验，不是论文复现时的跟踪网络训练。完整模型由训练入口移动到 GPU，但“参数在 GPU”与“参数参与梯度更新”不同。本分支此前选择的冻结策略不是 MVLM 论文规定。

## 实际权重和设备核验

比较 B 第400步检查点与父 A 第3000步检查点，所有变化均在 `future_fusion` 的12个参数张量；其他已保存模型张量完全一致。B 优化器只有12个参数张量及12份状态，不是整网优化器。

在独立空闲 GPU 上按同配置和检查点重建模型，所有参数、缓冲区均在 GPU；没有 CPU 卸载。当前 actor 对文本投影和视觉编码使用 `torch.no_grad()`；融合及 CENTER 输出可以建立梯度图，但 CENTER 权重被冻结，梯度只用于更新融合层。该核验没有执行优化器更新，临时进程已退出。

详细证据：`output/memory_world_stage_b_2gpu_b80_20261111_run01/analysis/stage_b_training_scope_audit_20261111.json`。

## 与论文官方训练实现的区别

作者的 [配置](https://github.com/inha-vllab/MVLM/blob/main/experiments/mvlm/mvlm_TF.yaml) 使用 `TYPE=text_frozen`、主学习率5e-4、编码器倍率0.1，以及权重0.5的 CM 损失；[优化器实现](https://github.com/inha-vllab/MVLM/blob/main/lib/train/base_functions.py) 冻结 CLIP，训练视觉编码器、语言投影和定位头。

当前 B 不训练这些跟踪模块，且只计算 `2*GIoU + 5*L1 + Focal`，没有 CM 损失。当前曲线只反映这一冻结适配策略，不能用于判断论文式联合训练的效果。

## 如果改为跟踪网络联合适配

- 保持 CLIP 本体冻结；训练视觉编码器、语言投影、CENTER 和融合层。是否同时解冻 A 模块应另行定义，不能混称“整网训练”。
- 同时修改阶段参数选择、encoder 的 train/eval 状态和 actor 的 no_grad 边界；仅修改 `FREEZE_ENCODER` 无法解冻当前阶段。
- 对照论文恢复 CM 监督，区分预训练跟踪网络的小学习率与新增层学习率。
- 当前一个样本是12帧片段，其中8帧可反传。若直接打开骨干梯度并保留整段计算图，显存可能大幅超过旧单帧训练；应先实现逐帧/小批反传与梯度累积，再实测全局80的两卡方案，必要时评估 AMP、激活检查点和卡数。
- 新方案应从明确检查点初始化、使用新输出与 W&B 运行。当前 B 可保留为冻结适配对照，不在原运行中途变更训练定义。
