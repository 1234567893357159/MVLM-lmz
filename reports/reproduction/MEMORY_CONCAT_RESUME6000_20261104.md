这些包含重复抽样。随机状态恢复不包括DataLoader worker与预取队列，不保证位级连续。

## 启动与隔离

```bash
CUDA_VISIBLE_DEVICES=4,5 /root/miniconda3/envs/mvlm/bin/python \
  tracking/launch_memory_concat_continuation.py \
  --parent output/memory_concat_2gpu_20261103_run01 \
  --out output/memory_concat_2gpu_20261104_resume6000_run01
```

只执行一次。若目录已存在，先核对监督进程和`training_status.json`，避免重复训练。
原4000步权重、结果与W&B运行均保留。续训创建独立W&B运行，在配置中记录父实验网址，
验证曲线包含4000步原结果，横轴沿用真实的4000～6000步。

模型、actor、采样器及评测程序从父实验实际使用的`source_retry01`复制，
仅替换预算控制、监督程序与审计工具。配置文件逐字节复用；其中旧`TRAIN.EPOCH=4`
不控制这个按更新次数运行的入口，实际停止预算由显式`--total-steps 6000`控制。
源码逐文件哈希与父检查点哈希写入新档案；原运行目录作为只读输入。

## 档案与验证

实时入口为新输出目录的`EXPERIMENT_RECORD.md`、`training_status.json`、
`training_metrics.jsonl`和`events.jsonl`。`audits/`保留逐段恢复的AdamW计数、
学习率、冻结参数哈希与双卡随机状态检查；`continuation_comparison.json`在完成后汇总
相对4000步和官方权重对照的AUC变化。标准测试集不参与训练或本次选模。

启动前16项检查通过，包括实际AdamW更新恢复一致性、显式预算限制、
中断后选择最新检查点以及续训退步时保留4000步候选。
