# concat 从4000步续训到6000步

2026-11-04用户明确授权执行，用于检查增加更新次数是否改善同一模型的留出验证表现。
父实验已完成，完整150条平均AUC为78.0844；同划分官方权重对照为78.4331。
这些是跟踪验证指标，不是分类正确率，也不是论文表格分数。

## 续训设置

| 项目 | 本轮设置 |
| --- | --- |
| 父实验 | `memory_concat_2gpu_20261103_run01` |
| 新输出 | `output/memory_concat_2gpu_20261104_resume6000_run01` |
| 恢复起点 | `MVLM_step004000.pth.tar`，包括模型、AdamW和双卡随机状态 |
| 起点SHA256 | `005807b6de6ae0391b18d097c495c0b33022182bc7bdea69148df6238f52478e` |
| 更新范围 | 4001～6000，增加2000次更新 |
| GPU / batch | 物理GPU4、5，每卡40个四帧片段，全局80 |
| 学习率 | 记忆1e-5，CENTER1e-6；不重新预热、不重置AdamW |
| 训练模块 | 记忆读取/融合/门控及全部扩展CENTER |
| 冻结模块 | 视觉与文本编码器、文本投影、CENTER BN运行均值/方差 |
| 其他策略 | FP32、AdamW、weight decay 1e-4、梯度裁剪1，与父实验一致 |
| 数据 | 相同固定训练清单、1:1:1来源采样、相同四帧与步长设置 |
| 检查点 | 每500步，独立保存4500/5000/5500/6000 |
| 验证 | 5000、6000步完整150条，使用原推理参数和协议 |
| 选模 | 同时保留原4000步候选，比较4000/5000/6000的完整验证AUC |
| 中断恢复 | 训练进程异常后从最新完整检查点重试，最多额外2次，保留失败日志 |

BN仿射参数仍参与训练。没有实现另外建议的“冻结原CENTER映射”，以保持本轮只改变训练预算。
累计6000步抽取480000次片段、1920000次搜索帧，新增160000次片段、640000次搜索帧；
这些包含重复抽样。随机状态恢复不包括DataLoader worker与预取队列，不保证位级连续。

## 启动与隔离

```bash
CUDA_VISIBLE_DEVICES=4,5 /root/miniconda3/envs/mvlm/bin/python \
  tracking/launch_memory_concat_continuation.py \
  --parent output/memory_concat_2gpu_20261103_run01 \
  --out output/memory_concat_2gpu_20261104_resume6000_run01
```

只执行一次。若目录已存在，先核对监督进程和`training_status.json`，避免重复训练。
原4000步权重、结果与W&B运行均保留。续训创建独立W&B运行，在配置中记录父实验网址，
验证曲线包含4000步原结果，横轴沿用真实的4000～6000步。

模型、actor、采样器及评测程序从父实验实际使用的`source_retry01`复制，
仅替换预算控制、监督程序与审计工具。配置文件逐字节复用；其中旧`TRAIN.EPOCH=4`
不控制这个按更新次数运行的入口，实际停止预算由显式`--total-steps 6000`控制。
源码逐文件哈希与父检查点哈希写入新档案；原运行目录作为只读输入。

## 档案与验证

实时入口为新输出目录的`EXPERIMENT_RECORD.md`、`training_status.json`、
`training_metrics.jsonl`和`events.jsonl`。`audits/`保留逐段恢复的AdamW计数、
学习率、冻结参数哈希与双卡随机状态检查；`continuation_comparison.json`在完成后汇总
相对4000步和官方权重对照的AUC变化。标准测试集不参与训练或本次选模。

启动前16项检查通过，包括实际AdamW更新恢复一致性、显式预算限制、
中断后选择最新检查点以及续训退步时保留4000步候选。仍需以真实双卡训练指标核验启动结果。
