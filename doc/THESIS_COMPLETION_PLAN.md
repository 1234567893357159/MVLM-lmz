| 论文主张 | 主要比较 | 结论边界 |
|---|---|---|
| 新增系统优于额外微调 | R4/R5 与 R1 | 优势属于整体新增设计；不能由此独立归因某一模块 |
| 内容库有助于预测系统 | R4 与 R3 | 保持近期历史、预测/融合接口、质量设置和训练策略一致；A 阶段也需配对 |
| 直接内容记忆有用 | R2 与 R1 | 结论限定于直接读取/融合方案，包含适配层的影响 |
| 学习预测比简单办法更有价值 | R3 与第 4.1 节的保持/外推替代方案 | 除离线预测误差外，必须看适配后的完整视频跟踪效果 |
| 质量设计有用 | R5 与 R4，加同一 R5 关闭重排的诊断 | 前者包含质量辅助训练和推理的总影响；后者只检查推理依赖 |
| 长期内容库有额外价值 | 完整库与仅短期库的配对版本 | 保留相同近期历史，并结合长期条目实际使用及重现场景指标 |

如果要进一步分别主张“质量监督有效”和“质量重排有效”，须分别控制训练监督与推理开关，不能仅凭 R5−R4 将两者分开。若要排除新增参数容量本身的解释，可进一步加入参数量相近、无未来预测目标的历史聚合适配器对照；仅报告参数量不能完成这种归因。

### 3.4 执行前必须统一的条件

2026-11-19 只读检查发现：旧 `mvlm_TF_memory_only.yaml`、`mvlm_TF_world_only.yaml` 冻结编码器和 BN 统计，当前 `mvlm_TF_memory_world_tracker_b_2gpu.yaml` 解冻编码器且更新 BN；旧 `world_only` 还启用了质量分支。这些配置不能直接组成正式消融表。仅修改 YAML 也不够，需核对实际训练入口和参数梯度。

每组试运行保存以下检查结果：

- 共同官方初始化及共享模块初始化种子；R3/R4 的 A 阶段训练数据、更新数、监督和选模规则相同，新增模块差异明确列出。
- 原跟踪器实际可训练参数名单、参数组学习率、优化器和调度器、BN 的训练/评估模式及统计更新规则；R1 不能用只训练 CENTER 的旧 `head_only` 代替。
- 相同训练/验证视频清单、来源比例、采样种子、片段长度、预热、全局 batch、有效监督规则和 B 阶段更新数。尽量复用采样序列；在线预测导致的裁剪差异属于系统行为，应记录。
- 相同坐标路径、首帧协议、推理参数、完整视频验证和检查点选择规则。固定终点可以作为主比较；验证选模时各组检查频率和候选预算一致。
- 短测确认关闭的模块不会隐式参与定位或损失，启用的模块确有调用、应训练的参数有有效梯度且冻结参数保持不变，状态不跨视频泄漏，权重保存与重载一致。

初始参考为当前 B 的 4000 更新、12 帧/预热 4 帧；若先做小预算筛查，各配对组使用同样预算。若统一策略改变了当前 B 的条件，不能直接复用旧 B4000 作为新表中的完整系统。

A 阶段属于新增模块的额外训练，必须单列数据使用、更新数和 GPU 时。R1/R2 没有相同 A 阶段，不得声称全流程计算预算相同；核心表先控制 B 阶段预算。如主张同总计算预算更好，再补训练成本匹配的基线，并分别报告样本暴露、更新数和计算时间。

完成标准：形成有明确比较关系的 R1～R5 表；优先完成 R1 和 R3/R4 核心比较。未完成某项时缩小对应贡献主张，不用不匹配的历史实验替代，也不预设所有模块均应有效。

## 4. 从现有权重开始的低成本诊断（先于新一轮大训练）

| 诊断 | 做法 | 记录什么 |
|---|---|---|
| 记忆是否有用 | 同一 B4000 分别正常读取、屏蔽读取；保留其他流程 | AUC/PRE/NPR、读写次数、库大小、读取条目年龄 |
| 长期库是否有用 | 比较完整库与仅近期历史/短期库，保持近期历史一致 | 长视频、遮挡重现片段的配对差值 |
| 预测是否有用 | 比较正常预测、旁路预测注入；单独控制质量分支 | 整体指标、融合门控、预测与观测一致性 |
| 质量重排是否有用 | 同权重、同参数比较质量权重 0 和固定正常值 | 排名改变比例、改变时选框 IoU 差值（GT 仅离线分析） |
| 世界预测是否超过简单办法 | 固定历史输入，先做预测器、上一帧特征保持和简单运动外推的离线诊断 | 特征误差/余弦相似度、框 IoU/位置误差，按时间间隔分组；正式跟踪比较见 4.1 节 |

先在固定验证集做，确认值得投入后补完整评测。已有质量权重搜索可复用作探索证据，不为重复表格重新运行完全相同的实验。

这些是推理干预，屏蔽输入可能造成训练/测试分布变化。下降说明模型依赖相应输入，不等于从头训练不带该模块一定更差；最终模块贡献仍以配对训练实验为主。

如果记忆读取极少、融合门控长期接近零，先排查数据流和门控；如果简单运动外推已达到类似水平，应如实报告并重新考虑预测器复杂度，不急于加深网络。

### 4.1 学习预测与简单替代方案的正式对照

优先在无内容库、无质量分支的 R3 设置下比较三种方案：学习预测；沿用上一帧 ROI 特征和框；沿用上一帧 ROI 特征并对位置作预先定义的简单运动外推。均只读取截至上一帧的信息，记录帧间隔、历史不足时回退和框裁剪规则。

尽量保持输出尺寸、坐标约定、融合接口及共同跟踪器一致，按同一 B 阶段预算分别适配融合层和跟踪器。若简单方案缺少预测器的隐变量或门控输入，须定义不依赖 GT 的替代，并将差异列入实验说明，不能用随意填充造成的退化支持预测器有效。

同一已训练模型直接替换预测只算推理诊断；各方案适配后的完整视频 AUC/PRE/NPR 才作为正式跟踪证据。离线误差使用统一历史样本便于隔离预测能力，在线评测各自维护预测历史以反映实际表现。预测误差较低不自动等于跟踪更好；两类结果都要报告。新增 A 阶段成本按 3.4 节单列。

### 4.2 长期库贡献的验证

若论文强调长期记忆，在相同短期容量、近期历史、写入可靠性及其他条件下，比较“仅短期库”和“短期＋长期库”。先做同权重推理诊断；若要主张长期结构带来收益，再配对训练两个版本。R3 保留近期历史但无内容库，不能替代这个短期/长期比较。

记录库占用、写入/淘汰次数、读取条目年龄分布、长期条目读取权重或贡献，以及完整视频和目标重现指标。读取过旧条目只能说明使用过，不能单独证明其有效。

当前训练片段 12 帧、前 4 帧预热且片段间清空状态，未必能建立或使用充分的长期库。先检查真实占用和读取日志；若训练中长期库几乎未被使用，则先完成配对的更长片段/预热短试，再讨论长期学习收益。保持视频状态独立，并控制有效监督帧数、样本暴露及计算成本，不能把更长训练本身混作长期库贡献。容量不同也可能影响结果；如主张收益来自长短期管理机制而非单纯存储更多内容，应补总容量相同的单库对照。

## 5. 围绕开题目标的场景分析（必须）

优先分析遮挡、目标离开画面后重现、相似目标干扰、快速运动、尺度变化和长视频。先检查数据集实际提供的属性标注；没有标注的场景可以人工标注少量固定视频，但应写明选取和标注规则。

至少交付：

1. **逐视频差值表**：相同视频的联合模型减基线 AUC，列出改善/下降数量、中位数、分位数，以及最大的改善与退化案例。
2. **属性子集表**：每类有多少视频/帧、基线和联合模型各是多少、差值是多少。属性可能重叠，不把各类简单相加。
3. **遮挡重现诊断**：若有可见性标注，预先定义遮挡事件、重现时刻和观察窗口；报告重现后固定窗口的平均 IoU、恢复比例和恢复等待帧数。未恢复事件必须计入失败，不能只统计成功案例。
4. **长时表现**：按视频长度分组，或者将每条视频等分为前/中/后段做配对统计；不要把本身更难的后半段下降直接归因为记忆失效。
5. **可视化**：至少各选择 3 个改善和退化案例，展示同一帧的 GT、基线框、联合框；附记忆读出/预测位置/门控信息中的必要部分，不只展示成功视频。

可以给出预注册式示例规则：目标重新可见后，连续 5 个有效可见帧 IoU≥0.5 算恢复；观察 100 帧，窗口不足和再次遮挡的处理提前定义。此规则是建议的项目诊断指标，不是数据集官方指标，需要在看结果前固定。

## 6. C 阶段及结构改动的决策（有条件开展）

**C 不是完成毕设的先决条件。** 只有在诊断提示冻结预测模块与已更新编码器不适配、或联合优化确有必要时，优先试 C。

开始前：适配当前完整 B 的加载和参数分组，不能直接运行旧开发配置；核验实际训练/冻结模块、BN 规则、梯度、检查点重载及训练/推理一致性。保留 B 原权重。

建议流程：先做数步功能与显存检查，再做 200～500 更新的短试；使用明确的低学习率分组，数值作为试验配置记录，不预先承诺其最优。保持跟踪损失及合适的预测监督，避免预测模块在联合训练时失去原任务约束。

同时做“B 继续训练相同步数”的对照，防止把额外训练时间误认为联合训练收益。只根据预先固定验证清单决定是否扩大预算；若指标恶化、预测退化或无稳定收益，保留 B 作为最终系统并记录负结果。

按诊断决定是否做下列结构实验，不一次全部展开：

- 记忆直接参与定位的旁路：仅在间接路径确有瓶颈证据时比较。
- 更长训练片段/预热：先确认库长度不足，控制有效监督帧总量和成本。
- BN 统计策略：现有结果并非统一支持换回旧统计；用独立副本在验证集比较，不能直接覆盖正式权重。
- 多步或扩散预测：只有开题/导师明确要求或已有证据支持时纳入，作为新研究任务估算成本。

## 7. 可信度与效率实验

**必须：**记录所有完整视频结果，按视频做配对分析。对主要 AUC 差值可用以视频为单位的配对 bootstrap 给出区间；不要把相邻帧当作独立样本。这种区间不覆盖训练随机性，也不消除测试集选参偏差。

**建议：**最终核心基线与联合模型使用至少 3 个训练随机种子，报告均值和离散程度。先完成单种子配对筛查，再把预算集中到最终两组；未做重复种子时明确限制。重复运行确定性推理不等于重复训练。

**必须：**相同硬件、精度、输入尺寸、软件条件下，测 R1 和最终模型的参数量、推理显存、FPS/单帧延迟；说明是否包含数据读取、语言编码和初始化，预热后计时，GPU 计时做同步。多视频并发的总吞吐与单视频延迟分别报告。

不要用 8 卡每卡多进程的搜索吞吐宣称模型单视频实时；“GPU 计算占满”与“显存填满”也不是同一个目标。正式成本估算从相同任务的短测外推，同时给出区间。
